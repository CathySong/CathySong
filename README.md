## How I Work

I like building systems that are useful enough to run repeatedly, not just demos that look good once. My default style is:

- define the decision the system should improve;
- make the data, assumptions, and scoring visible;
- ship a small working version;
- add evaluation so quality can improve over time;
- document the workflow so someone else can use it.
